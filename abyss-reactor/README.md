# P 深淵機関 ABYSS REACTOR — ナギバク研究所 NBL-001

ナギバク研究所オリジナルの架空パチンコ機の実機シミュレーター。ブラウザで動作。外部ライブラリなし、ビルド不要。
**実際の金銭・課金・換金機能はありません。**

## 起動

```bash
cd abyss-reactor
python3 -m http.server 8000      # 任意の静的サーバー
# → http://localhost:8000/
```

`index.html` を直接開いても（file://）動作する。ただし外部音源（assets/audio）は http 配信時のみ読み込まれる。

URL パラメータ：`?mode=stream`（配信表示）/`?mode=machine`（実機のみ）/`?auto=1`（オート遊技＋オートボタン）/`?autostart=1`（起動画面を飛ばす）

| 操作 | キー / 画面 |
|---|---|
| 発射 ON/OFF | Space ／ ハンドルをタップ |
| 発射強度 | ← → ／ ハンドルを上下ドラッグ ／ POWER スライダー |
| 左打ち⇔右打ち | R |
| プッシュボタン | Enter・B ／ 筐体のボタンをクリック |
| オート遊技（右打ち・ボタン自動） | A |
| 表示モード（通常→配信16:9→実機のみ） | S（Esc で通常へ） |
| 全画面 / 消音 / 開発者モード | F / M / D |

## スペック（`machines/abyss-reactor/spec.js` で変更可）

| 項目 | 値 |
|---|---|
| 通常時大当たり確率 | 1/99.9（16bit 乱数 65536 中 656） |
| 初当たり | 3R × 10C × 10玉 = 300玉 |
| RUSH 突入率 | 55%（当選時の別乱数で振り分け） |
| 深淵RUSH | ST31回 / 1/20 / 継続率 約79.6% |
| RUSH 中大当たり | 10R = 1000玉 → ST31回に再セット |

抽選は始動入賞時に乱数を取得し（保留）、変動開始時の遊技状態で判定する。演出用の乱数は抽選用と完全に別系統で、演出が当否や確率に影響する経路はない。

## 構成

```
engine/    core(名前空間・乱数) lottery(抽選) physics(玉物理) timeline(演出タイムライン)
           director(演出選択・シナリオ構築) game(状態管理) gimmick(役物制御) audio(音声) assets(素材)
render/    materials(質感) sprites(仮素材生成) machine(筐体・盤面) lcd(液晶) reels(図柄) gimmick(コア描画)
ui/        main(起動・入力・表示モード) datacounter(データカウンター) devtools(開発者モード)
machines/abyss-reactor/   spec / layout(釘・役物配置) / performance(演出テーブル) / sound(音) / assets(素材マニフェスト)
assets/    外部素材の置き場（docs/ASSET_LIST.md 参照）
tests/     run-tests.js（ヘッドレス検証）、debug/（スクリーンショット用スクリプト）
```

**新機種を作る場合**：`machines/<新ID>/` に同じ 5 ファイルを用意し、`index.html` のスクリプト読み込み先を差し替え、`?machine=<新ID>` で起動する。エンジン側の変更は不要。

## 主な機能

- **玉物理**：1/480 秒の固定刻み（描画 fps に依存しない。テストで 30/60/144fps 完全一致を確認）。外レール・発射レーン・逆流防止弁・釘（空間グリッド）・風車・ワープ→ステージ（前こぼれ／中央穴）・ヘソ・電チュー（普図連動）・アタッカー・一般入賞・アウト・ファール
- **通常時**：研究施設／深淵機関内部／警戒区域（先読みゾーン）の 3 ステージ、保留変化（入賞時／消化時）、予告、疑似連（×2〜×4）、テンパイ、ノーマルリーチ、発展
- **SP リーチ**：機関接続（SYNC ゲージ）／暴走制御（圧力計・制御棒 3 段階）／深淵覚醒（降下・巨大コア）。各々専用背景・BGM・テロップ色・カットイン・ボタン（通常／激）・役物、当たり／ハズレ両結末
- **ABYSS OVERDRIVE**：フリーズ→暗転→完全無音→鼓動→コア降下・展開→筐体レインボー発光＋衝撃波→最終ボタン
- **大当たり**：確定演出、ファンファーレ、ラウンド（実際にアタッカーへ入った玉で払い出し）、RUSH突入ジャッジ（7揃いは RUSH 確定告知）
- **深淵RUSH**：突入演出、専用背景・BGM・高速変動、残り回数表示、突発当たり、RUSH リーチ、深淵迎撃リーチ、ST 再セット、残り3回の専用演出、終了リザルト
- **配信向け**：オート遊技／右打ち／ボタン、16:9 配信モード、実機のみモード、データカウンター（総回転・初当たり・RUSH・最大連・累計出玉・差玉グラフ・履歴）、40 秒放置でデモ画面、10 秒ごとの自動セーブと再開
- **開発者モード（D）**：強制当たり／ハズレ、RUSH 強制突入・終了、SP・OVERDRIVE の個別再生、保留色と変化、確率・ST 回数の変更、命釘幅やワープ率などのスライダー、釘のドラッグ編集と書き出し、試射シミュレーション、再生速度、音量、抽選ログ、統計、テーブルから計算した信頼度、素材の表示確認、リセット。強制抽選や確率変更中の結果は「テスト統計」に分けて記録される

## テスト

```bash
node tests/run-tests.js            # 長時間稼働は既定 1800 秒相当
node tests/run-tests.js --long 7200
```

確率（300万回）、振り分け、RUSH 中確率、ST 継続率、テスト扱いの分離、物理の fps 非依存性、入賞率、状態遷移（初当たり→ラウンド→RUSH→ST消化→終了、RUSH 中当たり→再セット）、オートでの長時間稼働を検証する。

## 現状と未完成部分（正直な申告）

- **グラフィック・音声はすべて仮素材。** 筐体・盤面・役物・図柄・保留・液晶背景・エフェクトは Canvas でその場で描いており、音も WebAudio の合成音。質感（金属・クローム・ガラス・LED）にはかなり手をかけたが、商業機の水準に届かせるには外部素材が必要。`docs/ASSET_LIST.md` の仕様でファイルを `assets/` に置けば、コードを変えずに差し替わる（未配置なら仮素材に戻る）。
- 演出動画（`assets/movies`）を置いた時の再生フックは、マニフェストと LCD 側の背景動画再生までで止まっている。OVERDRIVE などで動画を本編として流すには、ディレクターに再生イベントを 1 行ずつ足す必要がある。
- 釘のゲージは自前のシミュレーションで調整した（左打ちのヘソ入賞率 約7〜10%、1000円あたり約18〜24回転）。好みに応じて開発者モードで再調整すること。
- ヘッドレスブラウザで描画を確認した fps はソフトウェア描画の数値で、実機ブラウザ（GPU 使用）での fps は未計測。
- 音量バランスは数値上で設計したが、実際に耳で確認したわけではない。
