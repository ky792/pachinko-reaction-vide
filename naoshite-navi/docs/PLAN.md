# なおしてナビ 開発計画と進捗報告（MVP v1.1 対応）

## 0. リポジトリについて

- `ky792/pachinko-reaction-vide` の `naoshite-navi/` 配下に、**単独で動く Next.js アプリ**として実装しています（既存の動画制作コードとは依存関係なし）。
- 仕様では「専用リポジトリ」が求められていますが、作業環境からリポジトリを新規作成できないため、切り出しやすい構成で開発しています。専用リポジトリへの移行手順は README の「専用リポジトリへの移行」を参照してください。

## 4. 機能の実装区分（デモと本物の区別）

| 機能 | 状態 |
|---|---|
| 業者検索（カテゴリ・地域・メーカー・今すぐ対応可）・並び替え | ✅ ロジックは本物（`search.ts`） |
| 比較（最大3社） | ✅ 本物（画面内） |
| おまかせマッチング（最大5社へ同時通知・先着1社） | ✅ ロジックは本物 |
| 指名依頼（1社のみ）・辞退時のおまかせ切替 | ✅ ロジックは本物 |
| 二重マッチング防止 | ✅ ロジックは本物（状態＋version＋オファー検査）/ DB 側はドラフト |
| 運営による状況変更 | ✅ ロジックは本物（許可された遷移のみ。「完了」は業者の完了報告でのみ） |
| 手数料記録（8%・上限8,000円） | ✅ 計算・記録は本物 / **請求・決済は未実装** |
| 権限制御・個人情報の表示制御 | ✅ ロジックは本物 / **ログインはデモ用（認証なし）** |
| データ保存 | ⚪ ダミー：localStorage（依頼・業者）、sessionStorage（検索条件・入力途中のフォーム） |
| 業者への通知 | ⚪ ダミー：画面内の通知レコードのみ。**SMS・メールは送信しない** |
| 業者の実績・資格・紹介文 | ⚪ 架空データ。「架空の業者（デモ）」「（架空）」を表示 |
| 口コミ・評価 | ❌ 未実装（「準備中」と表示。架空レビューは作らない） |
| 規約・プライバシーポリシー本文、審査書類添付、監査ログ | ❌ 未実装（画面に「未作成」「未実装」と表示） |

「当サイトでの完了件数」だけは、このデモ環境で実際に完了報告された件数を集計して表示しています。

## 5. 検証結果

- `npm run typecheck` / `npm run lint` / `npm run build` … OK
- `npm test`（vitest）… 45件 OK（手数料・候補抽出・検索・指名/おまかせ・二重マッチング・運営の状況変更・権限・個人情報の表示・入力検証）
- `npm run e2e`（Playwright・390px 幅）… 12段階すべて OK
  1. トップ → 製氷機1タップ → 症状1タップ → 検索結果
  2. 地域・メーカーで絞り込み、2社比較
  3. プロフィール表示 → ブラウザの戻るで絞り込み・比較リストが残る
  4. 指名依頼：入力 → 確認 → 戻る（入力が残る）→ 同意 → 送信
  5. 業者が指名を辞退 → 店舗がおまかせに切替
  6. おまかせ依頼（冷蔵・冷えない）の送信
  7. 先着1社が受諾、他社は「他社決定・終了」で連絡先非表示
  8. 完了報告で手数料記録（上限適用）
  9. 運営：状況変更・業者承認・手数料一覧
  10. 準備中の設備は検索・依頼不可
  11. 記事 → 検索導線、業者申請の入力チェック、受付状況一覧
  12. 主要12画面で横スクロールなし・ブラウザのエラーなし

## 6. 既知の制約

- データは端末内のみ（別端末と共有されない）。認証なし
- 進捗ページは URL を知っていれば同じ端末で閲覧可（Phase 2 で署名付きトークン）
- 通知の有効期限（無回答時の自動繰り上げ）、祝日カレンダーは未実装

## 7. Phase 2 で必要な設定

1. Supabase プロジェクト作成（開発・本番を分ける）、`supabase/migrations/0001_init.sql`（ドラフト）を v1.1 のモデル（カテゴリ・メーカー・プロフィール・指名依頼）に合わせて更新し、ローカルで RLS テスト

4. `src/lib/demo/` を Supabase 実装に置換
5. 通知手段の決定（送信開始は承認後）、規約・プライバシーポリシー作成
