# なおしてナビ 開発計画と進捗報告

## 0. リポジトリについて

`ky792/pachinko-reaction-vide` は動画制作（Python／GitHub Actions）用のリポジトリです。既存の `sns-studio/` と同じく、
本サービスは **`naoshite-navi/` 配下で独立して動く Next.js アプリ** として追加しました。既存コード・ワークフローには触れていません。
Vercel では「Root Directory = `naoshite-navi`」で取り込めます（将来は専用リポジトリへの分離を推奨）。

## 1. 全体計画

| Phase | 内容 | 状態 |
|---|---|---|
| **1** | 操作可能なフロントエンド（全6画面）＋業務ロジック（純粋関数）＋テスト。データはブラウザ内のダミー | **完了（このコミット）** |
| 2 | Supabase 接続：認証、DB、RLS、Server Action、業者通知（メール等）。**実データは扱わない**（ステージングでダミーのみ） | 未着手 |
| 2.5 | セキュリティ確認：RLS テスト、レート制限、監査ログ、プライバシーポリシー・規約の整備 → 承認後に実データ解禁 | 未着手 |
| 3 | 本番公開（承認後）、手数料の請求処理（承認後） | 未着手 |

### 設計の要点

- `src/lib/domain/` … 業務ルールを **フレームワーク非依存の純粋関数** で実装（候補抽出・状態遷移・二重マッチング防止・手数料・権限・表示データの絞り込み・入力検証）。Phase 2 ではサーバー側でそのまま再利用し、DB 関数・RLS と二重に守ります。
- `src/lib/demo/` … **Phase 1 専用のダミー**。localStorage に保存。Phase 2 で Supabase 実装に差し替え、ディレクトリごと削除します。
- 画面は `useDemo()` 経由でのみデータに触るため、差し替え範囲が限定されます。

## 3. 未実装・既知の制約（Phase 1）

- 認証なし。データは端末のブラウザ内のみ（別端末とは共有されない）
- 外部通知（メール・SMS・LINE・Push）なし
- 進捗ページは URL の ID を知っていれば同じ端末内で閲覧可（Phase 2 で署名付きトークン＋検索のレート制限）
- 通知の有効期限（一定時間無回答で次の業者へ）なし
- 業者の同時刻ダブルブッキング管理、営業日カレンダー（祝日）なし
- 審査書類のアップロード、監査ログ、データ保存期間後の削除なし
- 請求書発行・決済なし（承認なしに実装しない方針）

## 4. Phase 2 で必要な設定・作業

1. **Supabase プロジェクト作成**（開発用・本番用を分ける）。ローカルは `supabase start` で検証
2. `supabase/migrations/0001_init.sql`（設計ドラフト）をローカルに適用し、RLS のテスト（業者A が業者B の連絡先を読めない等）を作成
3. 環境変数（`.env.example` 参照）を `.env.local` と Vercel に設定。`SUPABASE_SERVICE_ROLE_KEY` はサーバー専用
4. 認証：業者はメールリンク（Magic Link）、管理者はメール＋多要素認証
5. `src/lib/demo/` を Supabase 実装（Server Action / Route Handler）に置き換え。依頼作成と進捗参照はサーバー経由のみ（anon に直接権限を与えない）
6. 業者通知の手段を決定（メール／SMS／LINE 公式アカウント）。**送信の実行は承認後**
7. 利用規約・プライバシーポリシー・加盟規約の作成（個人情報の利用目的・第三者提供＝担当業者への提供・保存期間を明記）
8. レート制限（依頼作成・受付番号検索）、ボット対策（Turnstile 等）
