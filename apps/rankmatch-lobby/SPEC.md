# 学習ランクマッチ：ナビゲーター選択 & ホーム 仕様

## 1. 体験の軸
- 受験勉強を「競技」として扱う。画面はゲームのロビーとして作り、学習管理アプリの見た目にしない。
- 主役はプレイヤー。ナビゲーターは専属の伴走者で、ランク・RP・学習量などプレイヤーの数値が常に画面の中心に来る。
- ボイスなし・フルアニメなし。立ち絵＋表情差分＋UI演出（ホログラム、走査線、ゲージ、ポップ）で見せる。

## 2. 画面フロー
```
#select（ナビ選択） --確定--> #home（ロビー）
#home --[ナビ変更]--> #select
```
- 初回は `#select`。確定後は選択内容を localStorage に保存し、次回は `#home` から始まる。
- ルーティングは `location.hash`（`#select` / `#home`）。

## 6. 実装構成（差し替えしやすさ優先）
```
apps/rankmatch-lobby/
  index.html            画面の器だけ（文言・画像なし）
  styles.css            トークンとコンポーネントの見た目
  data/navigators.js    キャラデータ（タイプ・男女・画像パス・セリフ・表情）
  data/mock-player.js   プレイヤーの仮データ
  js/components.js      UIコンポーネント（データを受け取ってHTMLを返す純関数）
  js/app.js             状態管理・ルーティング・イベント
  assets/navigators/    タイプ紹介キービジュアル（logic/halo/ignite/vex/echo.png）
                        将来の立ち絵は {typeId}/{charId}/{expression}.png
```
- テーマカラーは `data/navigators.js` の `types[].color` だけが正。JSが `--theme` などのCSS変数に流し込む。CSSにタイプ名を書かない。
- 画像は次の優先順で表示する（すべて `data/navigators.js` で決まり、コンポーネントは画像パスを持たない）。
  1. `portrait`：背景透過の単独立ち絵（未制作。現在は `null`）。表情キーごとにパスを持つ。
  2. `visual`：タイプ紹介キービジュアルの切り出し表示。画像は加工せず、`focus`（顔位置の%）と `zoom` で見せる範囲を決める。CSSのコンテナクエリで、どの枠サイズでも顔が中央付近に来るよう配置。
  3. `silhouette`：画像が読めないときのホログラム。
- キービジュアルは紹介用の暫定素材で、立ち絵の代わりではない。画像内の文字は読ませず、テキストはすべてHTMLで表示する。
- HALO / ECHO は改訂版の横長画像（縦316px前後）を使用。大きく表示すると拡大でぼやけるため、本番前に単独立ち絵の制作が必要。

## 9. ランクマッチ（非同期PvP・自動戦闘）
コアループ：**演習で学力を育てる → 学力で陣地戦に挑む → 敗因の科目を演習する**。対戦中にプレイヤーが問題を解くことはなく、クイズではなく「育てた学力のぶつけ合い」として見せる。

### 学力ステータス
- 5科目（国語・数学・英語・理科・社会）× 3能力（速さ・正確さ・応用、各0〜100）。科目の戦力＝3能力の合計。
- 演習（10問・1問15秒）で伸びる：正解数→正確さ、正解までの平均秒数→速さ、★2以上の正解数→応用。1セットで挑戦権+1。

### 対戦（`js/battle.js`）
- 相手はリアルタイムの対人ではなく**防衛データ**（相手プレイヤーの学力・ナビ・主戦場・陣地の並び）。`data/opponents.js` は仮データ。
- 流れ：相手を3人から選ぶ（格下・同格・格上、勝敗時のRPが異なる）→ 作戦（勝率予測・科目ごとの戦力比較・主戦場の選択・双方のナビ戦術）→ 自動戦闘の再生（2倍速・スキップ可）→ リザルト（RP、戦況分析、敗因科目の演習へ）。
- 陣地戦：相手の防衛順に5陣地を取り合い、先に3つ取ったほうが勝ち。各陣地は 速さ→正確さ→応用 の3回の押し合いで陣地ゲージが動き、最終的に自分側なら確保。各能力に±18%の揺らぎがある。
- 主戦場：選んだ科目の全能力 +10%。防衛時も、最後に使った主戦場が自分の防衛データになる。
- **ナビは強さに影響しない（原則）**：ナビのタイプによる数値補正は一切ない。勝敗を決めるのは学力ステータスと主戦場の選択だけ。
- ナビの役割は「提案」：作戦画面で、性格ごとの視点で主戦場を1つ提案する（LOGIC 勝率最大化／HALO 苦手を支える／IGNITE 先鋒で流れをつかむ／VEX 相手の得意を折る／ECHO 拮抗点を読む）。全科目について「主戦場にした場合の勝率」を全員に表示するので、どのナビを選んでも得られる情報は同じ。提案は採用してもしなくてもよい。
- 勝率予測は同条件で400回シミュレーションした勝率。
- 挑戦権：最大5。挑戦で−1、演習で+1。
- ナビのセリフ：`battleLines`（start / areaWin / areaLose / win / lose / train）。`{rate}` 勝率、`{focus}` 主戦場、`{subject}` 科目、`{weak}` 敗因（例：英語の速さ）、`{gain}` 成長量。

## 10. 知識データ（プレイヤーの実際の知識との連動）
学力ステータスは「貯めたポイント」ではなく「今の実力の推定値」。`js/knowledge.js`。
- 単元ごとに、実力レーティング（Elo 方式）・記憶の安定度・速さを持つ。問題側にも難易度レーティングがあり、全員の正答状況で自動調整される。
- 自分より難しい問題に正解すると大きく上がり、簡単な問題を落とすと下がる。知っている問題を繰り返してもほとんど動かない（連打・周回では伸びない）。4択の当てずっぽう分は補正する。
- 定着度＝exp(−経過日数／安定度)。間隔をあけて正解するほど安定度が伸びる（間隔反復）。誤答で縮む。
- 科目ステータス：正確さ＝単元平均の「標準問題の正答確率 × 定着度補正」（未学習の単元は低く数える）、速さ＝正解までの時間、応用＝★2以上の問題での実力、範囲＝学習済み単元の割合。
- **カンニングは黙認**：検知も禁止もしない。ただし画面上で「調べてOK」とは案内しない。調べて解いても定着するなら学習アプリとしては問題ない、という整理。演習は時間無制限。結果として、調べて正解すれば正確さと定着は伸び、時間がかかったぶん速さは伸びにくい（意図した対策ではなく、測定の副作用）。
- 自動戦闘の押し合いは「単元Aの正確さ → 単元Bの速さ → 科目の応用」。単元は両者共通で抽選。負けた単元がリザルトに出て、その単元を優先する演習へ直接進める。
- 出題は忘れかけ・未学習・対戦で押し負けた単元を優先。

## 11. 直接対決
- 自動戦闘で落とした陣地に納得できなければ、その科目の同じ5問を両者が解いて決め直す（1試合1回、1問30秒）。押し合った単元から優先して出題。
- 正解数が多いほうの勝ち。同数なら合計時間。勝てば陣地を奪還し、3陣地に届けば試合結果も逆転（RPを負け→勝ちに差し替え）。未戦闘の陣地が残れば自動戦闘で続ける。
- 解いた結果は自分の知識データにも反映される（対戦しながら学習になる）。
- 本番では相手もあとで同じ問題を解いて決着する（非同期）。試作では相手の知識データから回答を予測。

## 12. 陣地の表示とバトル演出（2D・アイソメトリック）
- 3D（Three.js）から 2D の Canvas 描画に変更した（`js/terrain2d.js`）。理由：キャラの2Dアニメ調と絵柄を揃える、課金アイテムを画像で量産しやすい、スマホで軽い。
- 斜め見下ろし（アイソメトリック 2:1）の陣地を「台座 → 庭（奥）→ 旗・エフェクト（奥）→ 周回物（奥）→ 建物 → 柱・庭（手前）→ 周回物（手前）→ エフェクト（手前）」の順に重ねて描く。
- 絵：`data/art-manifest.js` に登録された ID は `assets/territory/` の PNG を使い、それ以外はコードで描いた仮の絵（全85点ぶん）。規格は `ART_SPEC.md`、制作対象は `ART_LIST.md`。
- 陣地の色（持ち主の色）は、絵とは別の「チーム色マスク」をナビの色で塗って加算で重ねる。1枚の絵で5色に対応する。
- バトル演出は 3D 版と同じ流れ：開戦で上空から寄る → 陣地に寄る → 押し合い（自分色と相手色のエネルギーが衝突、火花、CRITICAL と揺れ）→ 陥落（衝撃波・光の柱・粒子・スタンプ・カットイン）→ 全景へ戻る。カメラの寄りは拡大表示、ドラッグで左右に動かせる。
- 呼び出し方は 3D 版と同じ（`create / setState / focus / intro / clash / capture / destroy`）なので、バトルとマイ陣地のコードはそのまま。

## 13. 単元の細分化（科目 › 分野 › 単元）
- `data/curriculum.js`：5科目 × 分野 × 単元（計69単元）と入試での出題頻度（★1〜3）。問題がある単元（現在52）だけが計算対象で、残りは「問題準備中」と表示する。問題を足せば自動で計算に入る。
- 学力の計算は出題頻度で重み付け（正確さ・速さ・範囲）。頻出単元を放置すると科目の数値が大きく下がる。
- 学力詳細画面（ホームの知識データから科目をタップ）：科目の3能力・範囲・平均定着度、分野ごとの正確さと範囲、単元ごとの状態（安定／標準／苦手／忘れかけ／未学習／問題準備中）・正答予測・定着度・速さ・解いた回数。各単元から演習へ。「忘れかけを復習」「苦手・未学習を攻める」のまとめ演習も。
- 対戦：押し合う単元は出題頻度で重み付けして抽選し、「分野 › 単元」で表示。押し合いごとに理由を両者の単元データから解説する（未学習を突いた／突かれた、正答予測の差、定着度の差、解答の速さ、揺らぎによる逆転）。
- リザルトの戦況分析では、負けた単元について両者の正答予測・定着度・速さを並べて表示する。

## 14. マイ陣地（カスタマイズと課金）
- **見た目だけ**：対戦の強さには一切影響しない。陣地の「持ち主の色」（自分＝ナビのテーマ色、相手＝相手ナビの色）は変えられない（対戦での判別性を守るため）。
- 項目（`data/cosmetics.js`）
  - 建物（科目ごと）：通常版は無料。特別版は 書院の塔（国語）／結晶の尖塔（数学）／古城（英語）／天文台（理科）／天守閣（社会）
  - 台座：標準／庭園／ネオン／白亜
  - 装飾（2つまで）：旗（文字入り・はためく）／灯籠／桜吹雪／天輪
  - 旗の文字：4文字まで自由入力（本番では不適切語のチェックを入れる）
- 入手：クリスタル（有償通貨）で**直接購入**（ガチャなし・価格表示）。一部は**学習の実績で無料開放**（7日連続学習→庭園、演習3セット→灯籠、直接対決で奪還1回→天輪）。課金しない人も育てられる。
- 見せ場：自分の陣地は、自分に挑む相手の対戦画面にこの見た目で出る。対戦では相手がカスタマイズした陣地に攻め込む（試作では3人の相手にカスタマイズ済みの見た目を設定）。
- クリスタル購入：60／320／680／1,400（¥120〜¥2,440）。**試作のため決済は行わない**。未成年の月額上限の例（15歳以下 5,000円、16〜19歳 10,000円）と保護者同意を画面に明示。実装時は法務確認のうえ決定する（前払式支払手段の扱い、年齢確認、返金方針など）。
- 画面：ホームの下部メニュー「マイ陣地」、またはホーム上部のクリスタル残高から。3Dプレビューに即反映し、建物タブでは選んだ科目の陣地にカメラが寄る。購入確認とクリスタル購入は画面内のシートで行う。

### 14-2. アイテムの量産（85点）
- `data/cosmetics.js` は「1行＝1アイテム」の表から量産する。3D は `js/cosmetics3d.js` がパラメータを読んで組み立てる。新しいアイテムは表に1行足すだけ（新しい形の建物・庭・周回物だけはビルダー関数を1つ足す）。
- 種類：建物20（各科目 通常＋特別3）／素材12（白磁・黒鉄・金箔・銀鏡・氷晶・ホログラムなど。持ち主の色以外の質感）／台座8（浮島・雪原・砂の遺跡・水鏡など）／庭14（3つまで配置。桜・松・竹・椰子・紅葉・石灯籠・鳥居・噴水・本棚・黒板・サーバーなど）／エフェクト13（雪・紅葉・蛍・星屑・泡・火の粉・光の雨・紙吹雪・音符・数式の雨・文字の雨など）／周回物10（本・惑星・サイコロ・歯車・折り鶴・ドローンなど）／旗の柄8（青海波・回路・市松など）
- レア度：COMMON 120 / RARE 220 / EPIC 350 / LEGEND 600 クリスタル。
- シリーズ（まとめ買い20%引き）：和の陣17点／サイバー8点／星空8点／学び舎7点。「まとめて試着」で全部を3Dで確認できる。
- 試着：未所持のアイテムはタップで3Dプレビューに重ねて表示し、画面下のバーから購入できる。所持品はタップで装備（庭は3つまで、タップで外す）。
- 実績での無料開放を追加（問題50問→白磁、演習1セット→本棚、10日連続→雪、直接対決3回奪還→数式の雨 など）。
- 対戦相手5人全員に、シリーズを組み合わせた見た目を設定（サイバー系・和風・天体系など）。

### 14-3. 科目ごとのカスタマイズと科目の小物

## 15. 防衛編成

## 18. 推定の精度改善（対象：大学受験）
- **対象は大学受験（共通テストレベル）に決定。** 既存の280問には中学レベルの問題も含まれるため、問題の量産（次の段階）で共通テスト水準に入れ替えていく。
- **推定の確かさ**：単元ごとに実力レーティングの不確かさ（sd）を持つ。初期 350 → 解くほど小さく（下限 100）。表示は「荒い／ふつう／確か」と、正答予測の幅（帯）。科目全体の確かさも学力詳細に表示。バトル解説では推定が荒い単元に「（推定はまだ荒い）」と添える。
- **動かし方**：不確かなうちは大きく、確かになるほど小さく更新（k = 0.45 × sd、最小16）。
- **科目全体の実力を手がかりにする**：科目ごとの実力も同時に推定し、初めて解く単元の出発点にする。解いた数が少ない単元は科目全体に少し寄せて、極端な推定を防ぐ。
- **答えの暗記を数えない**：3日以内に解いた同じ問題の正解は、更新量を4分の1にする（問題の難しさの推定にも使わない）。演習結果に「覚え◯」と表示。
- **実力に合った出題**：正答確率が五分五分に近い問題（情報量が多い）、推定が荒い単元を優先。最近解いた問題は避け、1セットで1単元に偏らない（最大で問題数の3分の1）。
- **シミュレーション結果**（数学、1セット10問）：60問解いた時点で単元ごとの正答予測の誤差は平均 ±9〜16 ポイント、200問で ±6〜11 ポイント。改善前は得意な人ほど大きく低く出ていた（正答率70%の人を37%と推定）が、偏りは ±0.1 前後まで縮小。上位・下位の端ではまだ中央寄りになるので、問題数（特に難しい問題と易しい問題）を増やすことで改善する。
