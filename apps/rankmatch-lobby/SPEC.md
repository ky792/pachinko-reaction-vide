# 学習ランクマッチ：ナビゲーター選択 & ホーム 仕様

## 1. 体験の軸
- 受験勉強を「競技」として扱う。画面はゲームのロビーとして作り、学習管理アプリの見た目にしない。
- 主役はプレイヤー。ナビゲーターは専属の伴走者で、ランク・RP・学習量などプレイヤーの数値が常に画面の中心に来る。
- ボイスなし・フルアニメなし。立ち絵＋表情差分＋UI演出（ホログラム、走査線、ゲージ、ポップ）で見せる。

## 2. 画面フロー
```
#select（ナビ選択） --確定--> #home（ロビー）
#home --[ナビ変更]--> #select
```
- 初回は `#select`。確定後は選択内容を localStorage に保存し、次回は `#home` から始まる。
- ルーティングは `location.hash`（`#select` / `#home`）。

## 3. ナビ選択画面

| 向いている学習スタイル | 箇条書き3つ＋「こんな人に」 |
| 確定ボタン | 画面下に固定（スマホ）。「{名前}と契約する」 |

### 男女差（特に HALO / ECHO）
- HALO ハル：頼れる先輩。落ち着いた低めのトーン、「〜だな」。計画を一緒に立てる。
- HALO ミオ：同級生の癒し系。共感と褒め、「〜だよ」。小さな達成を祝う。
- ECHO ノエル：書庫の賢者。丁寧語、論理で真理へ導く。「〜ですね」。
- ECHO セラ：星読みの巫女。詩的で謎めく、問いで返す。「〜かしら」。
- 他タイプは「同じ性格軸の中で温度差」を付ける（例：LOGIC レイ＝参謀／リゼ＝解析官）。

## 6. 実装構成（差し替えしやすさ優先）
```
apps/rankmatch-lobby/
  index.html            画面の器だけ（文言・画像なし）
  styles.css            トークンとコンポーネントの見た目
  data/navigators.js    キャラデータ（タイプ・男女・画像パス・セリフ・表情）
  data/mock-player.js   プレイヤーの仮データ
  js/components.js      UIコンポーネント（データを受け取ってHTMLを返す純関数）
  js/app.js             状態管理・ルーティング・イベント
  assets/navigators/    タイプ紹介キービジュアル（logic/halo/ignite/vex/echo.png）
                        将来の立ち絵は {typeId}/{charId}/{expression}.png
```
- テーマカラーは `data/navigators.js` の `types[].color` だけが正。JSが `--theme` などのCSS変数に流し込む。CSSにタイプ名を書かない。
- 画像は次の優先順で表示する（すべて `data/navigators.js` で決まり、コンポーネントは画像パスを持たない）。
  1. `portrait`：背景透過の単独立ち絵（未制作。現在は `null`）。表情キーごとにパスを持つ。
  2. `visual`：タイプ紹介キービジュアルの切り出し表示。画像は加工せず、`focus`（顔位置の%）と `zoom` で見せる範囲を決める。CSSのコンテナクエリで、どの枠サイズでも顔が中央付近に来るよう配置。
  3. `silhouette`：画像が読めないときのホログラム。
- キービジュアルは紹介用の暫定素材で、立ち絵の代わりではない。画像内の文字は読ませず、テキストはすべてHTMLで表示する。
- HALO / ECHO は改訂版の横長画像（縦316px前後）を使用。大きく表示すると拡大でぼやけるため、本番前に単独立ち絵の制作が必要。

## 7. 表情差分キー
`default`（通常） / `smile`（笑顔） / `serious`（真剣） / `special`（タイプ固有）
- ホーム：時間帯や状況で `default` / `smile` を出し分け。ランクマッチボタンにフォーカスで `serious`。
- 選択画面：プレビューは `default`、確定演出で `smile`。

## 9. ランクマッチ（非同期PvP・自動戦闘）
コアループ：**演習で学力を育てる → 学力で陣地戦に挑む → 敗因の科目を演習する**。対戦中にプレイヤーが問題を解くことはなく、クイズではなく「育てた学力のぶつけ合い」として見せる。

### 学力ステータス
- 5科目（国語・数学・英語・理科・社会）× 3能力（速さ・正確さ・応用、各0〜100）。科目の戦力＝3能力の合計。
- 演習（10問・1問15秒）で伸びる：正解数→正確さ、正解までの平均秒数→速さ、★2以上の正解数→応用。1セットで挑戦権+1。

### 対戦（`js/battle.js`）
- 相手はリアルタイムの対人ではなく**防衛データ**（相手プレイヤーの学力・ナビ・主戦場・陣地の並び）。`data/opponents.js` は仮データ。
- 流れ：相手を3人から選ぶ（格下・同格・格上、勝敗時のRPが異なる）→ 作戦（勝率予測・科目ごとの戦力比較・主戦場の選択・双方のナビ戦術）→ 自動戦闘の再生（2倍速・スキップ可）→ リザルト（RP、戦況分析、敗因科目の演習へ）。
- 陣地戦：相手の防衛順に5陣地を取り合い、先に3つ取ったほうが勝ち。各陣地は 速さ→正確さ→応用 の3回の押し合いで陣地ゲージが動き、最終的に自分側なら確保。各能力に±18%の揺らぎがある。
- 主戦場：選んだ科目の全能力 +10%。防衛時も、最後に使った主戦場が自分の防衛データになる。
- **ナビは強さに影響しない（原則）**：ナビのタイプによる数値補正は一切ない。勝敗を決めるのは学力ステータスと主戦場の選択だけ。
- ナビの役割は「提案」：作戦画面で、性格ごとの視点で主戦場を1つ提案する（LOGIC 勝率最大化／HALO 苦手を支える／IGNITE 先鋒で流れをつかむ／VEX 相手の得意を折る／ECHO 拮抗点を読む）。全科目について「主戦場にした場合の勝率」を全員に表示するので、どのナビを選んでも得られる情報は同じ。提案は採用してもしなくてもよい。
- 勝率予測は同条件で400回シミュレーションした勝率。
- 挑戦権：最大5。挑戦で−1、演習で+1。
- ナビのセリフ：`battleLines`（start / areaWin / areaLose / win / lose / train）。`{rate}` 勝率、`{focus}` 主戦場、`{subject}` 科目、`{weak}` 敗因（例：英語の速さ）、`{gain}` 成長量。

## 10. 知識データ（プレイヤーの実際の知識との連動）
学力ステータスは「貯めたポイント」ではなく「今の実力の推定値」。`js/knowledge.js`。
- 単元ごとに、実力レーティング（Elo 方式）・記憶の安定度・速さを持つ。問題側にも難易度レーティングがあり、全員の正答状況で自動調整される。
- 自分より難しい問題に正解すると大きく上がり、簡単な問題を落とすと下がる。知っている問題を繰り返してもほとんど動かない（連打・周回では伸びない）。4択の当てずっぽう分は補正する。
- 定着度＝exp(−経過日数／安定度)。間隔をあけて正解するほど安定度が伸びる（間隔反復）。誤答で縮む。
- 科目ステータス：正確さ＝単元平均の「標準問題の正答確率 × 定着度補正」（未学習の単元は低く数える）、速さ＝正解までの時間、応用＝★2以上の問題での実力、範囲＝学習済み単元の割合。
- **カンニングは黙認**：検知も禁止もしない。ただし画面上で「調べてOK」とは案内しない。調べて解いても定着するなら学習アプリとしては問題ない、という整理。演習は時間無制限。結果として、調べて正解すれば正確さと定着は伸び、時間がかかったぶん速さは伸びにくい（意図した対策ではなく、測定の副作用）。
- 自動戦闘の押し合いは「単元Aの正確さ → 単元Bの速さ → 科目の応用」。単元は両者共通で抽選。負けた単元がリザルトに出て、その単元を優先する演習へ直接進める。
- 出題は忘れかけ・未学習・対戦で押し負けた単元を優先。

## 11. 直接対決
- 自動戦闘で落とした陣地に納得できなければ、その科目の同じ5問を両者が解いて決め直す（1試合1回、1問30秒）。押し合った単元から優先して出題。
- 正解数が多いほうの勝ち。同数なら合計時間。勝てば陣地を奪還し、3陣地に届けば試合結果も逆転（RPを負け→勝ちに差し替え）。未戦闘の陣地が残れば自動戦闘で続ける。
- 解いた結果は自分の知識データにも反映される（対戦しながら学習になる）。
- 本番では相手もあとで同じ問題を解いて決着する（非同期）。試作では相手の知識データから回答を予測。

## 12. 陣地の3Dモデル
- `js/terrain3d.js`（Three.js r128 を cdnjs から読み込み）。外部の3Dデータは使わず、基本図形の組み合わせで科目ごとの陣地を作る。
  国語＝積み重ねた本と筆、数学＝浮かぶ多面体、英語＝地球儀と輪、理科＝原子模型、社会＝ピラミッドとオベリスク。
- 六角形の台座が相手の防衛順に弧状に並ぶ。持ち主の色で縁・建造物・光の柱が光る（自分＝ナビのテーマ色、相手＝相手ナビの色、交戦中＝白の点滅、未決＝ニュートラル）。陣地を取ると色が切り替わり、建造物が跳ねる。
- 作戦・自動戦闘・リザルトの各画面に表示。ドラッグで左右に回転。自分の主戦場の上に回転するマーカー。
- キャンバスは1つを使い回し、画面の再描画ごとに新しい置き場所へ移す（WebGL を作り直さない）。WebGL が使えない環境では非表示にして、2Dの陣地タイルだけで遊べる。
- 本番で作り込んだモデルに差し替えるときは、`structure()` を glTF の読み込みに置き換える。
