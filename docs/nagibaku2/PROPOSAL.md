## A. 今の制作システムの問題点と改善方針

### A-1. 残すもの（そのまま使う）
| 仕組み | 理由 |
|---|---|
| **Remotion（React で動画を組む）** | 共有記憶で決定済み（`render.engine`）。コードで全部書けて、GitHub Actions で書き出す流れもできている。フラッシュ式（パーツの切り替え＋移動・回転・拡縮）と相性がいい |
| **音声の関門（`voice_gate`）** | 台本にない声・言い切れていない声・作り直したのに未検査の声を、行ごとの sha1 付きで落とす。2.0 の「台本の厳密管理」の土台にそのままなる |
| **`precheck` ＋ `tts_pitfalls.json`** | 「ちょっと」「短い一言」など、崩れやすい言い回しを声を作る前に止める蓄積 |
| **台本の書式**（`話者: 台詞`、`《漢字|よみ》`、行ID `k01-030`） | 行IDが声・字幕・検査で共通になっている |
| **図解の部品**：`PixelJob`（就活ドット絵）・`SlotFlow`（フロー図）・ホワイトボード風カード・年表カード | 2.0 でもそのまま「図解テンプレート」として使える |
| **公式表情集（ナギ8・バク8）、休憩室・研究所の背景、効果音、RNC-01** | 公式デザインの基準。描き直さない |

### A-2. 変えるもの
| 問題 | 何が起きるか | 直し方 |
|---|---|---|
| **キャラが「1枚絵の差し替え＋跳ねる・拡大」だけ** | 口が動かない、まばたきもない。表情を変えるたびに体ごと切り替わる | パーツ分けしたキャラ（リグ）にして、口・目・耳・尻尾・腕を別々に動かす（B・D） |
| **素材の解像度が低い**（キャラ 約320〜440px） | 寄りのカメラを使うとぼやける。今の画面でも拡大表示している | 高解像度のマスター画像を新たに用意（C） |
| **同じ絵に別の名前が付いている** | 例：`kyu/nagi/angry.png` と `sad.png`、`smug.png` と `point.png`、`kyu/baku/confused.png` と `sweat.png` が同じファイル。名前で選ぶと意図と違う顔が出る | 表情集の番号と名前（「①通常・無表情」等）を正本にした素材台帳を作る |
| **旧デザインがリポジトリに残っている** | `reference_nagi_baku.png`（目が開いたナギ・赤ジャケットのバク）、`characters/nagi/`・`baku/`・`old/`・`cat/`・`rabbit/` など。取り違えると公式デザインが崩れる | 消さずに `_deprecated/`（使用禁止）へ移し、エンジンから読めないようにする |
| **エピソードごとに巨大なコード**（`KyukeiEpisode.tsx` 987行、`NewsEpisode.tsx` 1133行） | 次の回で使い回しにくい。毎回作り直しになる | キャラ・カメラ・字幕・図解を共通部品に分け、回ごとのファイルは「どの部品をいつ使うか」だけにする |
| **演出の指示が台本ファイルに混ざっている**（`@show` `@hl` など） | 演出を直すたびに台本ファイルを触る。台本の字面が変わる事故の入口になる | 台本（セリフだけ・ロック）と演出表（行IDで参照）を別ファイルにする（D-4） |
| **音声の関門が「回せば止まる」仕組み** | 過去に関門を回さずに書き出してハルシネーションが入った（LESSONS 指摘5） | 書き出しの最初に関門を必須で走らせ、合格していない行が1つでもあれば書き出さない |
| **開発がブランチに散らばっている**（`feat/kyu001-remotion`・`feat/kyu001-voice`・`feat/shared-memory` が main 未マージ、memory-inbox も未処理） | 「main の memory/MEMORY.md を読め」が成立しない。どれが最新か毎回調べる必要がある | 2.0 に着手する前に、承認をもらって main に統合する（D-7 の Phase 0） |

## B. ナギバク2.0 の映像表現方針

### B-1. 基本の考え方：「動かすところだけ動かす」フラッシュ式
- **常時（ほぼ自動）**：口パク・呼吸（ゆっくり上下 1〜2px）・バクのまばたき・ナギのタンクの気泡と発光・バクの尻尾。これだけで「止まった絵」ではなくなる。
- **セリフの頭だけ（演出表で指定）**：表情の切り替え、うなずき、首かしげ、身を乗り出す、ツッコミの腕。
- **見せ場だけ（1分に1〜2回）**：全身ポーズの差し替え（表情集の大リアクション）、カメラの急な寄り、画面揺れ、効果線。
- **動かさない**：図解を読ませている間のキャラ（口パクと呼吸だけ）、ナギの目。

### B-2. キャラごとの演技
| | ナギ | バク |
|---|---|---|
| 基本 | **無表情・淡々**。体はほぼ動かさない | **リアクション豊か**。話す頭で少し跳ねる |
| 目 | **常に閉じたまま**（共有記憶 `nagi.eyes`）。まばたきもしない | 開き・半目・閉じ（まばたき）・見開き・ジト目を切り替え |
| 口 | 小さく3〜4段階。開き幅を抑えて淡々さを出す | 4〜5段階＋牙。叫ぶ台詞は大きく |
| 耳 | **立ち耳だけ**ゆっくり揺れる。驚き・疑問で立ち耳がピンと立つ／少し傾く（折れ耳は動かさない） | 驚きでピクッ（Phase 2） |
| 体 | うなずき・首かしげ（頭パーツの回転 3〜6°）。タブレットに目を落とす | 跳ねる・前のめり・ツッコミの腕・腕組み |
| 小物 | 背中の脳タンク：液の発光がゆっくり脈打つ、気泡が上がる（コードで描く）。タブレット画面の光 | ゴーグルのレンズにキラッ（コード）、尻尾がゆらゆら |
| 記号 | 汗・「…」・「！」は控えめに（表情を顔で作らない分、記号と耳で伝える） | 汗・怒りマーク・「!?」・集中線を使ってよい |
| 大リアクション | ほぼ無し。使っても「⑥びっくり」「⑤ため息」くらい | 表情集「⑤テンションMAX」「⑥怒り」「⑦あたふた」を全身差し替えで使う（「⑧号泣・笑いすぎ」は負けの場面で使わない：`kyu.ochi_face`） |

> 補足：ご指示の「目・眉・口による表情変化」は、ナギには共有記憶の「目を開けさせない」を優先して、口・耳・頭の角度・記号で表現します。

### B-3. カメラ
| ショット | 使いどころ |
|---|---|
| **2ショット（基本）** | 普通の会話。ここに長くいてよい |
| **寄り（片方のバストアップ）** | オチの一言、ナギの鋭い指摘、バクの大リアクション |
| **図解ショット**（キャラを画面の端に小さく、図解を中央に） | 数字・仕組みの説明 |
| **引き（背景ごと）** | 章の頭、場面転換、オチの間 |

- **切り替えるのは「情報が変わる」「リアクションが出る」ときだけ**。同じ構図で何往復か続く会話はそのまま（カメラはゆっくり 1〜3% 寄り続けるだけ）。
- 寄り・引きは 8〜12 フレームのイージング、ツッコミは 3〜4 フレームの急な寄り（パンチイン）。
- 「話している方に毎回カメラを向ける」はしない（せわしなくなる）。
- 共有記憶の「同じ画面を続けない（会話だけの区間にも資料・アニメを入れる）」は、**カメラを振るのではなく、図解や小道具を足す**ことで満たす。

### B-4. 図解・文字
- 休憩室回：ホワイトボード風カード、フロー図アニメ、就活ドット絵（既存の部品）。
- 新台解説：号外風（紙地×黄×太い墨線）、スペックは円グラフ（中に文字）か表。
- ニュース：ニュース番組風（報道台・指し棒）。
- 字幕は**台本の字面から作る**（文字起こしからは作らない）。強調語だけ色・大きさを変える。
- 数字・仕様は公式資料で確かめたものだけ（発明品のルールと同じ）。

### B-5. 「間」の使い方
- ボケとツッコミの間：0.2〜0.4 秒（無音のまま、カメラも止める）。
- ナギの淡々とした一言の前：0.3〜0.5 秒、キャラは呼吸だけ。この「止め」がナギの面白さになる。
- 大オチの前：BGM を切って 0.6 秒（共有記憶 `bgm.volume`：オチで無音になるのが分かるように）。

## D. 制作システムの実装計画

### D-1. 方式の比較と推奨
| 方式 | 良いところ | 悪いところ | 移行コスト |
|---|---|---|---|
| **① Remotion＋自作のパーツ式リグ（推奨）** | 今の仕組み・図解・音声の関門をそのまま使える。全部コードなので台本→動画を自動化できる。口パクを音声データから自動で付けられる。パーツを増やすほど表現が増える | 絵がぐにゃっと曲がる動き（メッシュ変形）はできない（＝カクッとしたフラッシュ調。今回の狙いには合う）。パーツ素材が要る | コード：試作まで1〜2週間（こちらの作業）。お客様側：素材の生成と確認で数時間 |
| ② Live2D | 表情・揺れが滑らかで本格的 | パーツ分け＋リギングが専門の手作業（1体数十時間）。書き出しの自動化が難しい。年商によりライセンス費 | 大。外注なら1体数万〜数十万円 |
| ③ Rive / Spine | ボーン・メッシュ変形ができる | リギングは専用エディタで手作業。Spine は有料。Remotion でコマ単位に正確に描かせるのに一手間 | 中〜大 |
| ④ After Effects / Animate で手作業 | 自由度が最も高い | 1本ごとに手作業。自動化できない | 毎回大 |

**推奨は①。** 将来「この場面だけは滑らかに動かしたい」となったら、その場面だけ ②〜④ で作った動画を差し込めるようにしておく（特殊演出の差し込み口：D-5）。Live2D 化は、IP として育ってグッズ・実機化の段階になってから改めて検討すれば十分。

### D-2. パーツ分け（リグ）
**正面・座り（上半身）の1アングルから始める。** 向きの変更（横向き・斜め）は Phase 3。

> ⚠ **左右反転は使えません。** ナギは折れ耳と脳タンクの位置、バクは胸の肉球ワッペンの位置が左右非対称なので、反転すると公式デザインと変わります。向きを変えるには、その向きの素材が別に必要です。

**ナギ（奥から順に）**
| 層 | パーツ | 動き |
|---|---|---|
| 1 | 体（脳タンク・ジャケット・ハーネス・タブレットを持つ腕まで一体） | 呼吸の上下、うなずき時に少し沈む |
| 2 | 頭（口なし・目は閉じたまま描かれている） | 回転 3〜6°（うなずき・首かしげ） |
| 3 | 立ち耳（N-04 があれば） | 根元を軸にゆっくり揺れる／驚きでピンと立つ |
| 4 | 口（閉・小・中・お） | 口パク |
| 5 | コードで描く層 | タンクの発光と気泡、タブレットの光、汗・記号 |
| 差し替え | 全身ポーズ（表情集③考え中・⑤ため息・⑥びっくり・⑦どや） | 見せ場だけ |

**バク（奥から順に）**
| 層 | パーツ | 動き |
|---|---|---|
| 1 | 尻尾（B-05 があれば） | ゆらゆら |
| 2 | 体（作業服・ベルト・下ろした腕） | 呼吸、話す頭で跳ねる |
| 3 | 頭（目なし・口なし、ゴーグル込み） | 回転・前のめり |
| 4 | 目（開き・半目・閉じ・見開き・ジト目） | まばたき（2〜5秒にランダム、乱数は固定で毎回同じ）、表情 |
| 5 | 口（閉・小・中・大＋牙・お） | 口パク |
| 6 | コードで描く層 | ゴーグルのキラッ、汗・怒りマーク・「!?」・集中線 |
| 差し替え | 全身ポーズ（表情集①〜⑦） | 大リアクション |

- 各キャラの部品は `rig.json`（画像・重ね順・回転の軸・位置）で定義し、Remotion の共通部品 `<Puppet>` が描く。
- **表情はプリセット名で呼ぶ**（例：`baku: jito` ＝ ジト目＋口閉じ）。表情集の番号と対応させた `expressions.json` を正本にする。

### D-3. 音声と口パクの同期
| | ナギ（AivisSpeech） | バク（Irodori） |
|---|---|---|
| タイミングの取り方 | 声を作るときの `audio_query` に入っている**モーラごとの長さ**から、母音（あいうえお・ん）の時刻を正確に出す | 台本の読み（pyopenjtalk）と、関門で使っている Whisper の単語ごとの時刻、音量の波形を合わせて推定 |
| 口の形 | 母音→口：あ＝中、い・え＝小、う・お＝「お」、ん・無音＝閉（大きく開けない） | あ＝大、え＝中、い＝小、う・お＝「お」、ん・無音＝閉 |
| 共通 | 口の形は 30fps で1コマずつ決め、2コマ未満のちらつきは消す。叫ぶ台詞は音量で1段大きく。声ファイルの sha1 で保存し、声を作り直したら自動で作り直す |

- 既存の kyu001v2 の音声には時刻情報が保存されていないので、試作ではナギもバク式（推定）で付け、同じ台詞で `audio_query` を取り直して精度を比べる。

### D-4. 台本・音声の厳密な管理（台本外のセリフを入れない仕組み）
1. **台本はロックする**：`script.txt`（セリフだけ）→ `script.lock.json`（行ID・話者・字面・読み・sha1）。演出表やコードは行IDで参照するだけで、字面には触れない。
2. **声は台本の行からしか作らない**：行IDに無い声は作れない。相づち・叫び・笑いを足す機能を持たせない。
3. **関門を書き出しの入口にする**：`precheck`（作る前）→ 声を作る → `asr_check`＋`voice_gate`（作った後）→ 合格（sha1 一致）の行だけが動画に入る。1行でも未合格なら書き出さない。
4. **字幕は台本の字面から**。文字起こしは検査にだけ使う。
5. **話者の取り違えを止める**：行の話者と声のモデル（ナギ＝コハク「ねむたい」、バク＝Irodori garo2_fix_s53）が一致しないと止める。口パクも行の話者のキャラにしか付かない。
6. **変更は提案ファイルに**：台本の言い回しを変えたほうがいい箇所（TTS が崩れる等）は `episodes/<回>/proposals.md` に「行ID・今・案・理由」で書き、**承認をもらってから台本に反映**する。
7. **耳での確認**：関門は機械的な一致率で判定しているため、「バク→僕」「内定→泣いて」のような聞き違いでも合格することがある。一致率が低めの行を一覧にして、耳で確認してもらう候補として出す。
8. 見つけた崩れは今までどおり `tts_pitfalls.json` に足す。

### D-5. 演出表と動画の書き出し
- **演出表** `episodes/<回>/direction.yaml`（行IDで書く）
  ```yaml
  - at: k01-032          # この行の頭で
    cam: baku_up_punch   # カメラ
    baku: {pose: kyu_02_wink, fx: shuchusen}   # 表情集②の全身差し替え＋集中線
    se: emphasis
  - at: k01-034
    cam: nagi_up
    nagi: {tilt: 5, ear: perk}
    pause_before: 0.3
  - at: k01-030..k01-033
    board: {component: PixelJob, mode: job}    # 既存の図解部品
  ```
- 書いていない行は「前の状態のまま・口パクと呼吸だけ」。だから全行に指示を書く必要はない。
- **特殊演出の差し込み口**：`clip: special/xxx.mp4` で、別ツールで作った動画（透過 WebM も可）をその行に重ねられる。
- 書き出しは今と同じ GitHub Actions（push で mp4 と確認用の静止画が `outputs-*` ブランチに保存される）。

### E-3. 確かめること（合格の目安）
1. **口パク**：声と口のずれが目で分からない（目標：1〜2コマ以内）。ナギが淡々と見えるか、バクが元気に見えるか。
2. **デザインの維持**：公式表情集と並べて、耳の形と本数・脳タンク・ゴーグル・毛色・服が同じか（並べた比較画像を一緒に出す）。
3. **演技の差**：ナギが動きすぎていないか、バクが大げさすぎないか。
4. **読みやすさ**：図解が出ている間にキャラが邪魔をしていないか。
5. **作業量**：素材が揃ったあと、演出表を書いてから書き出しまでにかかった時間（こちらの作業）と、お客様の手作業がどれだけあったか。
